# Gemini 3.1 Pro — Prep and implementation checklist

**Source:** `docs/gemini3.1update.json`  
**Goal:** Support the new Gemini 3.1 Pro API in the promptctl CLI (add provider + API changes).

---

## 1. API changes to implement

| # | Change | Notes |
|---|--------|--------|
| 1 | **Add `gemini-3.1-pro`** | New supported model; implies adding a Google/Gemini provider if not present. |
| 2 | **Replace `thinking_budget` with `thinking_level`** | API now uses `thinking_level`: `"low"` or `"high"`. |
| 3 | **Add `media_resolution`** | Values: `"low"`, `"medium"`, `"high"` — controls vision processing. |
| 4 | **Usage tracking** | PDF tokens are under `IMAGE` modality in `usage_metadata`, not `DOCUMENT`. |
| 5 | **Multimodal function responses** | Functions can return images and PDFs alongside text; handle in tool-calling logic. |

---

## 2. CLI surface (from cursor_prompt)

- **`--thinking-level`** — choices: `low`, `high` (maps to API `thinking_level`; replaces any existing `thinking_budget`).
- **`--media-resolution`** — choices: `low`, `medium`, `high` (vision/multimodal).
- **Provider:** Add Google/Gemini provider in `llm/provider.go` with model `gemini-3.1-pro`; wire BaseURL, EnvKey (e.g. `GOOGLE_API_KEY` or Vertex), and Complete path.
- **Token logging:** When processing Gemini responses, read PDF token metrics from `usage_metadata` under `IMAGE`, not `DOCUMENT`.
- **Tool calling:** Extend handler to support function responses that include images/PDFs (multimodal).

---

## 3. Implementation prompt

Use the **cursor_prompt** value from `docs/gemini3.1update.json` when ready to implement (it’s a full Cursor prompt for the five changes). Optionally paste it into a new chat and reference this prep doc.

---

## 4. Pre-implementation checklist

- [ ] Confirm Gemini/Vertex API base URL and auth (API key vs service account).
- [ ] Decide provider key in `Providers`: e.g. `"google"` or `"gemini"`.
- [ ] Locate where `thinking_budget` is used (if any) so it can be replaced by `thinking_level`.
- [ ] Locate token/usage logging and any `DOCUMENT` modality handling.
- [ ] Locate tool/function-calling response handling for multimodal extension.
- [ ] After implementation: run cost/model tests and update CHANGELOG + docs.
